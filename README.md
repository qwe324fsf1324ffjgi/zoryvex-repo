## The Mission

Hiring should be about more than what a CV claims. It should be about credible evidence, demonstrated ability, and trust.

Zoryvex aims to help employers and candidates move toward a more evidence-driven hiring experience by bringing identity verification, skills assessment, and professional reputation signals together.

> **Trust should be demonstrated, not merely claimed.**

### Architecture Components

| Layer                       | Technologies                             | Purpose                                                |
| --------------------------- | ---------------------------------------- | ------------------------------------------------------ |
| Frontend and edge           | Amazon CloudFront, Amazon S3             | Global content delivery and static frontend hosting    |
| API layer                   | Amazon API Gateway, AWS Lambda           | API routing and serverless application execution       |
| Authorization               | Custom Lambda authorizer                 | Centralized authorization and access enforcement       |
| Data                        | Amazon DynamoDB, Amazon S3               | Application data, assets, and backups                  |
| Infrastructure as Code      | Terraform                                | Version-controlled infrastructure provisioning         |
| Observability               | Amazon CloudWatch, Grafana               | Logs, metrics, alarms, and dashboards                  |
| Security                    | AWS WAF, AWS Shield, AWS Secrets Manager | Web protection, DDoS protection, and secret management |
| Networking and certificates | Amazon Route 53, AWS Certificate Manager | DNS management and TLS certificates                    |
| Email                       | Amazon SES                               | Transactional email delivery                           |
| External integrations       | Paystack, GitHub OAuth                   | Payment processing and supported authentication flows  |

*The diagram represents the intended architecture and its integrations. Actual deployed services, configuration, and production readiness should be verified against the current AWS environment.*

## Engineering Principles

### Security by design

Use controlled access, managed secrets, encrypted services, and layered protection to reduce avoidable security risks.

### Infrastructure as Code

Use Terraform to make infrastructure changes reviewable, repeatable, and easier to audit.

### Reliability engineering

Design operational checks, health endpoints, backups, recovery procedures, and monitoring around the possibility of failure.

### Serverless efficiency

Use managed services and event-driven execution where appropriate, with attention to cost, scaling, and operational overhead.

### Observable systems

Use logs, metrics, alarms, and dashboards to improve visibility into system behavior and support troubleshooting.

### Evidence-driven development

Validate changes through automated tests, security checks, and controlled deployment procedures rather than relying on assumptions.

## Reliability, Security, and Scalability

The architecture emphasizes several important engineering goals:

* **Global access:** Content delivery through a CDN.
* **Managed execution:** Serverless application components.
* **Controlled access:** Authentication and authorization boundaries.
* **Operational visibility:** Logs, metrics, and alarms.
* **Recovery readiness:** Backups and restoration procedures.
* **Cost awareness:** Monitoring infrastructure spending.
* **Repeatable delivery:** Infrastructure managed as code.

These are architectural goals and design considerations, not a guarantee of uptime, security, or production readiness.
