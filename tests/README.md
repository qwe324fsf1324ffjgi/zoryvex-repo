# Tests

This is the cross-cutting test area referenced by `docs/ARCHITECTURE.md`. Per-package unit tests stay
colocated with their code (`apps/web/tests`, `services/api/tests`, `packages/*/tests`) — that pattern is
already in place and run by `npm test`. This directory is for suites that span more than one package or
need a real running/built artifact rather than an isolated unit.

| Subfolder        | Status              | Notes                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `contract/`      | Colocated instead   | `packages/contracts/tests/*.test.ts` already validates every schema; a dedicated top-level suite is added here only if a future contract test genuinely needs to span multiple packages.                                                                                                                                                                                                                           |
| `integration/`   | Colocated instead   | `services/api/tests/http-adapter.test.ts` and `packages/local-adapters/tests/*` already cover their respective integration seams. A dedicated suite lands here once there's a real cross-package integration worth testing separately.                                                                                                                                                                             |
| `security/`      | Not yet populated   | No authenticated surface exists in the real backend yet (see `docs/THREAT_MODEL.md` — the auth flow is designed, not built against a real API). The local-adapters' `AuthAdapter` enumeration-resistance and single-use-code behavior is already covered in `packages/local-adapters/tests/local-auth-adapter.test.ts`. A dedicated suite lands here once there's a real session/authorization boundary to attack. |
| `accessibility/` | Populated (Phase 4) | Playwright + `@axe-core/playwright`, run against the real static export via `scripts/serve-static.mjs`. Browser install was previously blocked in this sandbox; retried in Phase 4 and `cdn.playwright.dev` is in fact reachable — Chromium and WebKit both install and run locally now, in addition to CI.                                                                                                        |
| `e2e/`           | Populated (Phase 4) | Same Playwright setup, desktop + mobile (`playwright.config.ts` projects). Grows with each page/flow as it's built.                                                                                                                                                                                                                                                                                                |

Nothing in this directory is a placeholder green test — an empty, documented gap is preferred over a test
that doesn't actually assert real behavior.
